# R3: Naming and brand collision check

Run date: 2026-10-21. Researcher: R3 agent. Scope: 59 candidate names (35 original + 10 new + 14 added by the coordinator mid-run). No winner is picked here.

## How to read this (3 lines)
- Verdict CLEAR means: no brand, book, course or GitHub-org collision found in the searches I could run. It does NOT mean trademark-clear (no USPTO/WIPO search was possible). Several CLEAR names still have a registered .com whose owner I could not identify.
- **.ai and .io columns are weak.** RDAP for both was blocked (see Method), so the only signal is "does the name resolve in DNS". TAKEN[D] is reliable. UNKNOWN[D] means "no A record" and is NOT evidence of availability: 5 of 14 .com names that had no A record turned out to be registered in RDAP (agentfluency, agentcraft, delegatewell, steerwell, helmwork).
- Cell codes: **[R]** = RDAP answer (404 = AVAILABLE, 200 = TAKEN). **[D]** = DNS lookup only (resolves = TAKEN; no A record = UNKNOWN for .ai/.io).

1. Clean on both .com and .dev (RDAP 404 on both) and with no brand hit: **Mode Fluency, Delegation Engineering, Agentmanship, Reinsmanship, Agentic Numeracy, The Calculator Problem, AI-Human Engineering Stack (slug aihumanengineeringstack), Tillerwork, Delegation Ladder**. Of these, Delegation Ladder, Mode Fluency and Delegation Engineering read as the most usable; Delegation Engineering is the one DeepMind's Feb 2026 paper (https://arxiv.org/abs/2602.11865) is pushing toward becoming a mainstream topic.

Hard no: **Directing Intelligence** (a forthcoming 2027 book on the same theme, https://www.penguinrandomhouse.com/books/855716/directing-intelligence-by-edwin-jansen/), **Articulate** (major e-learning incumbent in the same L&D market), **AIES** (academic conference acronym), **Agentcraft, Cockpit, Conductor, Specwork, Tokencraft, Workcraft** (taken).
3. "Fluency" is the incumbent umbrella word (Anthropic AI Fluency, Salesforce AI Fluency Playbook Jan 2026, Udacity Agentic AI Fluency). "Agent Boss" is Microsoft's phrase from the April 2025 Work Trend Index (https://blogs.microsoft.com/blog/2025/04/23/the-2025-annual-work-trend-index-the-frontier-firm-is-born/), aimed at the same office-worker audience.

5. "Mission Command" and "Commander's Intent" are doctrine terms, already applied to AI agents (https://warontherocks.com/2026/08/stop-using-ai-start-commanding-it/). Strong metaphors, not ownable.

## 2. Method and limits

Tools available: curl, python3 (socket resolver). `dig` and `whois` were NOT installed; whois port 43 to whois.nic.io and whois.nic.ai timed out.

1. **DNS first, for all 59 names x 4 TLDs (236 lookups).** `socket.getaddrinfo(name.tld)` through the system resolver. A name that resolves is registered (TAKEN[D]). A name that does not resolve was then sent to RDAP where RDAP was usable. A raw UDP DNS query to 1.1.1.1 returned bogus empty answers in this sandbox, so NS-record checks were not possible.
2. **.com via RDAP:** `https://rdap.verisign.com/com/v1/domain/NAME.com`, run only for names whose .com did not resolve (16 names). 404 = AVAILABLE[R], 200 = TAKEN[R].
3. **.dev via RDAP:** `https://pubapi.registry.google/rdap/domain/NAME.dev`, run for every .dev name that did not resolve (46 names). 404 = AVAILABLE[R], 200 = TAKEN[R].
4. **.ai and .io: RDAP unavailable.** `https://rdap.identitydigital.services/rdap/domain/...` (the IANA bootstrap server for .ai, https://data.iana.org/rdap/dns.json) and `https://rdap.org/domain/...` returned HTTP 429 with Retry-After of about 22,000 seconds, from this proxy IP. `.io` is not listed in the IANA bootstrap at all, and rdap.nic.io / rdap.nic.ai did not connect. Therefore .ai and .io rest on DNS only: resolves = TAKEN[D]; no A record = UNKNOWN[D] (the name may be registered but unparked, or reserved). No .ai/.io name is marked AVAILABLE.
5. **GitHub:** `api.github.com` is blocked and plain curl to github.com returned 403 through the proxy (34 wasted requests). I used WebFetch on `https://github.com/NAME` for 25 shortlisted names: 404 = no such user/org, 200 = exists. Repo-level popularity (for example a famous repo called "specwork" under another owner) was not searched except through one web search.
6. **Brand/book/course:** 28 web searches (limit 30). Search results are noisy and the search tool is not an exact-phrase engine; "none found" means the searches turned up nothing, not that nothing exists. No USPTO, EUIPO or WIPO trademark search was possible, so every trademark statement is UNVERIFIED unless a URL is given.

Limits to keep in mind:
- RDAP 404 on .com/.dev means "not registered right now". It does not rule out registry-reserved or premium-priced names (common on .dev and .ai), and prices were not checked.
- DNS-resolves proves registration; no-A-record proves nothing. Registered-but-parked-without-A-record domains were seen (5 .com, 3 .dev: articulate.dev, theprincipal.dev, signoff.dev were registered despite not resolving).
- Domain ownership was never looked up (WHOIS/RDAP bodies were not read). "Owner unidentified" means just that. poniclabs.com resolves; whether the client owns it is UNVERIFIED.
- Genericness judgments are mine, with one cited usage where I found one.

**Spot-check of AVAILABLE results with a second method (DNS):** 5 .com AVAILABLE results re-checked by DNS: modefluency.com, tillerwork.com, delegationladder.com, agentmanship.com, agenticnumeracy.com all returned no DNS record, 5 of 5 agree. Across all AVAILABLE[R] cells (10 .com, 43 .dev) every one also had no A record; 0 disagreements. Caveat: the reverse is not true (the DNS-first stage missed 8 registered domains), so DNS is the weaker method; RDAP is the authoritative one.

**Budget deviation (disclosure):** Planned limit was 80 HTTP requests plus 25 extra for the coordinator's add-on names, and 30 searches. I used roughly 133 HTTP requests (including 34 wasted GitHub curls that returned 403 and 6 blocked RDAP probes) and 28 searches. The overrun came from checking every .dev name via RDAP and from GitHub checks. Nothing was skipped as a result, but flag it.
