## How to read this
- **Domain cells.** [R] = RDAP answer (404 = AVAILABLE[R], 200 = TAKEN[R]). [D] = DNS only (resolves, or NS delegated = TAKEN[D]). UNKNOWN[D-NX] = DNS-over-HTTPS returned NXDOMAIN from the .io zone. That strongly suggests the name is not delegated, but it is NOT an RDAP answer, so it is never reported as AVAILABLE. **.ai RDAP worked in this run** (it was blocked for R3), so .ai AVAILABLE cells are RDAP-backed. **.io RDAP was still blocked** (HTTP 429, Retry-After 78,743 s).
- **Trademark.** Only USPTO could be queried. EUIPO and WIPO were blocked and Chrome was not available (see Method), so every row's EU/WIPO status is **UNVERIFIED**. "USPTO: no exact hit" means no wordmark containing the exact phrase or the slug turned up in USPTO's search index (live or dead).
- **Search shadowing.** The "top 3" column lists the first three results from the WebSearch tool for the exact phrase in quotes. This tool is not Google or Bing, so ranks are indicative only.
- **Verdict.** CLEAR = no exact-name company or product, no live mark found, and no single dominant incumbent in search. CROWDED = several same-space users or near-exact collisions, but none that owns the name. TAKEN = an exact-name company or product, or a live mark, in an adjacent space. GENERIC = a descriptive phrase, job title or term of art that cannot be owned.

## 2. Method and limits

Tools: Bash (curl, python3 `socket`), WebFetch, WebSearch. `dig` and `whois` are not installed. Chrome (claude-in-chrome) tools were **not available** in this session (a tool search for "claude-in-chrome" returned nothing), so the Chrome fallback was not used and the chrome-browser skill was not loaded. Chrome actions: 0.

1. **DNS (no HTTP):** `socket.getaddrinfo` for all 96 name.tld pairs. Control: a random nonsense .com and .ai did not resolve, and google.com did, so the resolver does not wildcard.
2. **.com RDAP:** `https://rdap.verisign.com/com/v1/domain/NAME.com`, run for the 6 .com names that did not resolve, plus modewise.com. Three of the six (deliberateai.com, aisteering.com, agentmodes.com), and also modewise.com, were registered despite having no A record. This repeats R3's warning that "no A record" proves nothing.
3. **.ai RDAP:** `https://rdap.identitydigital.services/rdap/domain/NAME.ai` (the IANA bootstrap server). Unlike in R3, it answered this time, with intermittent HTTP 429. Each 429 was retried once after 8 s, and two names a third time later. Validation: google.ai returned 200. It was run for all 20 .ai names that did not resolve, plus modewise.ai. Two were registered despite having no A record (agentry.ai, chiefofagents.ai). All other non-resolving .ai names returned 404 = AVAILABLE[R].
4. **.io:** RDAP at the same server returned 429 with Retry-After 78,743 s, so it was not usable. As a second signal I queried Google DNS-over-HTTPS (`https://dns.google/resolve?name=NAME.io&type=NS`) for the 22 non-resolving .io names. 20 returned NXDOMAIN (Status 3, authority `io.`), recorded as UNKNOWN[D-NX]. Two, workingintelligence.io (AWS NS) and agentcharter.io (Cloudflare NS), are delegated, so they are TAKEN[D]. NXDOMAIN is not an RDAP 404, so per the brief no .io is marked AVAILABLE.
5. **Trademarks:**
   - **USPTO (worked):** the public search UI's backend, `POST https://tmsearch.uspto.gov/prod-stage-v1-0-0/tmsearch`, is an Elasticsearch-style endpoint. I sent one batched query with `match_phrase` on the wordmark field `WM` for 65 variants (each name with spaces, each slug, plus "agent wise", "agent work", "agent modes", "modewise", "ai rated", "agents at work"). It returned 22 records, all reported above, live and dead, across all classes. Field validity was confirmed with a control query (COURSERA and AGENTRY returned 7 hits). Limits: phrase-matching on the wordmark only. It does not cover design marks without text, phonetic or near-spelling variants, or broader single-word marks (for example, plain MODUS, STEER or KATA marks were not searched). It is not a legal clearance opinion.
